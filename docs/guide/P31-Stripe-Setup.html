Connecting Stripe:
one account for each site

Exactly where to click in Stripe, what to copy, and where to paste it in Supabase, so that p31market.com and thep31collective.org each take payments into their own Stripe account. About 45 minutes the first time.

Before you start

  • Two Stripe accounts. If you only have one, make the second now: in Stripe, click your account name in the top-left corner and choose New account. Name one Proverbs 31 Marketplace and the other P31 Collective. Switch between them the same way.
  • Each account activated. Stripe asks each one for its business details, a bank account for payouts and a statement descriptor (what shows on a card statement, for example P31 MARKET and P31 COLLECTIVE). Use the legal business that runs each site.
  • The Supabase secrets page open in another tab:
    https://supabase.com/dashboard/project/xsnhxjttdizljaawpumz/functions/secrets
    Each value goes in as a Key (the name, exactly as written here) and a Value (what you copied), then Save. Functions read new secrets straight away; nothing needs redeploying.

Keep keys secret. Copy from Stripe and paste straight into Supabase. Do not paste them into a document, an email, a text or this chat. If a key is ever exposed, open API keys in Stripe, use the ⋯ menu on that key, choose Rotate key, and paste the new one into Supabase.

Part 1 · The Collective account

Mentorship and coaching payments

Switch to the Collective account first (account name, top-left). About 15 minutes.

1 · The secret key

  1. Open API keys: https://dashboard.stripe.com/apikeys (also under Developers or Workbench).
  2. Under Standard keys, find Secret key and click Reveal live key. Click the key to copy it. It starts with sk_live_.
  3. In Supabase, add Key COLLECTIVE_STRIPE_SECRET_KEY, paste the Value, and Save.

2 · The webhook (so the site knows when someone has paid)

  1. Open Webhooks in Workbench: https://dashboard.stripe.com/webhooks, and click Create an event destination.
  2. Choose Your account.
  3. For the payload format choose Snapshot, not Thin. Leave the API version as it is.
  4. Select these five events (type each name in the search box):
    • checkout.session.completed
    • invoice.paid
    • invoice.payment_failed
    • customer.subscription.updated
    • customer.subscription.deleted
  5. Click Continue, choose Webhook endpoint, and click Continue.
  6. Endpoint URL: https://xsnhxjttdizljaawpumz.supabase.co/functions/v1/academy-webhook
    Description: P31 Collective · mentorship. Create it.
  7. On the destination’s page, find the Signing secret (starts with whsec_), click Reveal secret and copy it.
  8. In Supabase, add Key COLLECTIVE_STRIPE_WEBHOOK_SECRET, paste, Save.

3 · The customer portal (clients update their card or cancel)

  1. Open https://dashboard.stripe.com/settings/billing/portal (Settings → Billing → Customer portal).
  2. Click Activate link. Allow customers to update payment methods and view invoices. For cancelling, choose at the end of the billing period, which matches the agreement’s notice terms. Save.

4 · How it looks to clients (5 minutes, optional but worth it)

  • Settings → Branding: upload the Collective hands logo, brand colour plum #3A1C36, accent gold #D9A93A.
  • Settings → Public details: business name The P31 Collective by NEBA, support email members@thep31collective.org, the website thep31collective.org.

That is the Collective done. No products or prices to create in Stripe: the site sends each client’s price (from Systems → Academy) with her payment link.

Part 2 · The Market account

Shop card payments, vendor payouts, storefront subscriptions

Switch to the Market account. About 25 minutes, most of it Stripe’s Connect questions.

1 · Connect (lets vendors get paid into their own bank accounts)

  1. Open https://dashboard.stripe.com/connect/registration (or Connect in the menu, then Get started) and complete the platform profile. When asked how it works: a marketplace, where vendors sell to shoppers, shoppers pay the platform, and the platform pays the vendor and keeps a fee.
  2. Open the Connect settings, https://dashboard.stripe.com/account/applications/settings, and set the branding vendors see when they connect: name Proverbs 31 Marketplace, colour #3A1C36, the Market icon. Stripe requires this before the first vendor can connect.

2 · The secret key

  1. https://dashboard.stripe.com/apikeys → Standard keys → Secret key → Reveal live key, then copy it.
  2. In Supabase, add Key MARKET_STRIPE_SECRET_KEY, paste, Save.

3 · Webhook A: the Market’s own payments

  1. https://dashboard.stripe.com/webhooks → Create an event destination → Your account → Snapshot (not Thin).
  2. The same five events as the Collective:
    • checkout.session.completed
    • invoice.paid
    • invoice.payment_failed
    • customer.subscription.updated
    • customer.subscription.deleted
  3. Continue → Webhook endpoint → Continue. Endpoint URL:
    https://xsnhxjttdizljaawpumz.supabase.co/functions/v1/stripe-webhook
    Description: P31 Market · orders and storefronts.
  4. Reveal and copy its signing secret, and keep the tab open for a minute. This is secret A.

4 · Webhook B: vendors’ payout accounts

  1. Create an event destination again, but this time choose Connected accounts, then Snapshot.
  2. One event: account.updated.
  3. Same endpoint URL as A: https://xsnhxjttdizljaawpumz.supabase.co/functions/v1/stripe-webhook
    Description: P31 Market · vendor payout accounts.
  4. Reveal and copy its signing secret. This is secret B.
  5. In Supabase, add Key MARKET_STRIPE_WEBHOOK_SECRET with the Value A, a comma, then B, with no spaces:
    whsec_AAAAAAAA,whsec_BBBBBBBB

5 · The fee, the portal, the look

  • In Supabase, add Key PLATFORM_FEE_PERCENT with Value 5: the 5% the Storefront Agreement keeps from each card sale.
  • https://dashboard.stripe.com/settings/billing/portal → Activate link, so vendors can change the card on their $14.99 subscription or cancel.
  • Settings → Branding (Market logo, plum and gold) and Public details (Proverbs 31 Marketplace, vendor@p31market.com, p31market.com).

Part 3 · Switch it on

Deploy, then the one switch in Vercel

The secrets are read straight away. The functions just need the latest code once.

1 · Deploy the payment functions (once)

From the project folder:

npx supabase functions deploy stripe-webhook academy-webhook academy-checkout academy-billing vendor-billing stripe-checkout stripe-connect stripe-account-status join-notify watchdog --no-verify-jwt --use-api --project-ref xsnhxjttdizljaawpumz

2 · Turn on card checkout in the shops (when you are ready)

This switch shows Pay by card in the bag and the Connect Stripe button in each vendor’s studio. Coaching payment links and the vendors’ $14.99 subscription work without it.

  1. In Vercel, open the P31 project → Settings → Environment Variables.
  2. Add Key VITE_ENABLE_CARD_PAYMENTS, Value true, for Production (and Preview if you like). Save. This is a switch, not a secret: never put a Stripe key in Vercel.
  3. Open Deployments, open the ⋯ menu on the newest one, and choose Redeploy. The switch takes effect when that finishes.

Part 4 · Test, then go live

Prove it with a test card first

Recommended: do Parts 1 and 2 in each account’s sandbox first, test, then repeat the key and webhook steps in live mode.

How the sandbox works

  • In each Stripe account, switch from live mode to its Sandbox (the mode switch at the top of the Dashboard). Sandbox keys start with sk_test_, and sandbox webhooks have their own whsec_ secrets.
  • Put the sandbox values into Supabase under the same names. When the tests pass, create the live key and live webhooks in live mode and replace each value in Supabase (open the secret, edit, save).
  • Test card: 4242 4242 4242 4242, any future date, any 3-digit CVC, any ZIP. Nothing is charged in a sandbox.

Test the Collective

  1. Mentor console → Invites → New invite, with your own email and any plan (or Agreements → Send payment link for a test client).
  2. Open the link, create the account with that email, and pay with the test card.
  3. The classroom opens. In Stripe → Webhooks → the academy destination → Event deliveries, each event says Delivered (200).

Test the Market

  1. Subscription: sign in as a test vendor → Studio → Plan & billing → Set up my subscription → test card. Her plan shows as set up.
  2. Card sale (after the Vercel switch): the vendor clicks Connect Stripe in her studio and fills the test onboarding. Then buy one of her products by card. The order lands in her Orders, with emails to both.
  3. Both stripe-webhook destinations show Delivered (200).

If something is not right

You seeFix
Event deliveries show 400 and “Signature error”The webhook secret in Supabase does not match that destination: a sandbox secret with live keys (or the reverse), or B missing from the Market’s A,B. Copy it again.
Event deliveries show 500 “Not configured”A key name is misspelled in Supabase. Compare with the table in Part 3, letter for letter.
Deliveries say Delivered, but the classroom or order never updatesThe destination was made with the Thin payload. Delete it and make it again with Snapshot, then paste the new signing secret.
“Card payments aren’t connected yet” on a payment link or subscriptionThat site’s secret key is missing, or the functions were not deployed (Part 3, step 1).
A vendor’s Connect Stripe button gives an errorFinish the Market’s Connect platform profile and the Connect branding (Part 2, step 1).
No Pay by card in the bagEither VITE_ENABLE_CARD_PAYMENTS is not true in Vercel (and redeployed), or that vendor has not finished connecting Stripe. Order requests keep working either way.

When both sites pass in live mode, tell Claude and it will run a quick check of the deployed functions and the database to confirm everything is talking to the right account.
